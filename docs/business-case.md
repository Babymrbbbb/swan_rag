## 三、「业务 → 架构 → 指标」通用叙事框架

面试/简历被问"你这个项目解决了什么业务问题"时，按三段式回答，避免陷进技术细节：

```
1. 业务（Why）：谁、在什么场景、痛什么、规模多大
   → "43 家门店的一线员工，查标准 SOP 靠口口相传，分钟级且易走样。"
2. 架构（How）：你做了什么关键设计决策，为什么
   → "用 RAG 而非直接问 LLM：向量召回锁定资料范围 + 生成带原文引用，
      并用供应商解耦抽象隔离真实 LLM，避免厂商锁定。"
3. 指标（What）：可量化的结果或目标
   → "方案目标查询秒级、咨询人工量降 30%+；已用真实 LLM 验证架构可行，
      并在评测闭环中证明可抑制幻觉。"
```

**反模式（务必避免）**：
- ❌ "我做了一个 RAG demo"（像玩具，触发 JD 一票否决）。
- ✅ "我为 43 店连锁设计了 AI 知识中台方案，架构已用真实 LLM 验证，目标把一线查询降到秒级"（像业务+架构师）。
