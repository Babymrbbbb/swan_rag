## 三、「业务 → 架构 → 指标」通用叙事框架

面试/简历被问"你这个项目解决了什么业务问题"时，按三段式回答，避免陷进技术细节：

```
1. 业务（Why）：谁、在什么场景、痛什么、规模多大
   → "47 家门店的一线员工，查标准 SOP 靠口口相传，分钟级且易走样。"
2. 架构（How）：你做了什么关键设计决策，为什么
   → "用 RAG 而非直接问 LLM：向量召回锁定资料范围 + 生成带原文引用，
      并用供应商解耦抽象隔离真实 LLM，避免厂商锁定。"
3. 指标（What）：可量化的结果或目标
   → "方案目标查询秒级、咨询人工量降 30%+；已用真实 LLM 验证架构可行，
      并在评测闭环中证明可抑制幻觉。"
```

**反模式（务必避免）**：
- ❌ "我做了一个 RAG demo"（像玩具，触发 JD 一票否决）。
- ✅ "我为 47 店连锁设计了 AI 知识中台方案，架构已用真实 LLM 验证，目标把一线查询降到秒级"（像业务+架构师）。

## 五、门店智能体 POC 口径（面向零售 AI 岗/门店智能体方向）

> 背景：零售 AI 岗（如汇通达「AI 零售产品经理-门店智能体方向」35-50K）要求"完整 0-1 落地门店 AI POC 并定义试点指标（巡检准确率/补货预测准确率/店长减负率/单店 ROI）"。
> 本段把 swan_rag 从"RAG 知识中台"升级为"门店智能体 POC"的指标化叙事——**方案目标指标明确标注为"目标"，已实现能力标注为"已验证"**，不虚标。

### 5.1 门店智能体 POC 定义（方案）

以 swan_rag 知识中台为底座，把「一线员工查 SOP / 查新品 / 查政策」的被动问答升级为**门店智能体**：

| 能力模块 | 实现方式 | 状态 |
|---|---|---|
| 门店知识问答 | RAG（向量召回 + LLM 生成 + 原文引用） | ✅ 已实现 + 真实 LLM 验证 |
| 一线 SOP / 新品 / 政策检索 | 知识库分层（门店网络/新品/加盟/运营FAQ） | ✅ 已实现 |
| 评测闭环 | golden-set 回归 + 检索命中率阈值 | ✅ 已实现 |
| 数据可靠性 | 真相源 + 自愈索引 + 接地测试 | ✅ 已实现 |
| 门店巡检 / 补货预测 / 智能体编排 | 需接入门店 IoT/POS/库存数据 | 🟡 规划中（POC 扩展） |

### 5.2 POC 试点指标体系（方案目标值，非已验证）

| 指标 | 定义 | 方案目标值 | 状态 |
|---|---|---|---|
| **巡检准确率** | 门店智能体对巡检问题（SOP 合规/陈列规范）回答与人工复核一致的比例 | ≥ 90% | 🟡 目标 |
| **店长减负率** | 一线重复咨询由智能体承接的比例 | ≥ 60% | 🟡 目标 |
| **补货预测准确率** | 接入库存数据后补货建议与实际上架需求匹配度 | ≥ 85% | 🟡 规划 |
| **单店 ROI** | （节省工时成本 - 智能体运行成本）/ 单店年成本 | ≥ 5× | 🟡 规划 |
| **检索命中率** | golden-set 上检索召回命中比例（离线已验证） | ≥ 75% 阈值 | ✅ 已验证 |

### 5.3 POC 落地路径（0-1 叙事）

```
第 0 步（已完成）：知识中台架构 + 真实 LLM 验证 + 评测闭环 + 数据护栏
第 1 步（规划）：接入品牌内部真实 SOP/新品/竞品文档（数据合规评审）
第 2 步（规划）：接入门店 POS/库存/会员数据，扩展检索范围
第 3 步（规划）：定义试点门店与基线（人工承接量/查询耗时/错误率）
第 4 步（规划）：上线试点，按 5.2 指标体系采集数据，输出 POC 报告
```

### 5.4 一句话 POC 口径

> "我基于 47 家门店连锁的实际业务，设计了门店知识智能体的 POC：用 RAG 让一线员工'问即得、带出处'，用评测闭环和自愈索引保证答得准、答得稳；并定义了巡检准确率、店长减负率、单店 ROI 等试点指标，为从方案走向门店试点提供了可度量的路径。"
